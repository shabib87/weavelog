## Start here: the release we are building

**Done is better than perfect. Incremental releases are better than a big bang.
Stop yak shaving.** The operational rules live in
[repository AGENTS.md](../../AGENTS.md#shipping-discipline).

[Open the release diagram](./release-dependencies.html). The existing milestone
and this brief own release scope; individual tasks own live status, dependencies
and verification evidence. TASK-67 owns final installed-package proof and the
human release decision; TASK-63 owns publication enforcement. TASK-45 is the
one-time release-baseline correction, not a permanent tracker. Earlier dated
notes are provenance wherever this summary or the corrected order supersedes them.

| Question | Agreed answer |
|---|---|
| What ships? | One explicitly started TypeScript-controlled OpenCode workflow, using the existing roster, skills and hooks, plus independent npm setup on arm64 macOS. |
| What must setup preserve? | Full ADR-0008 conflict refusal, confirmed replacement, protected backups, journaling and recovery; no fresh-install-only shortcut. |
| Who tests it? | The author can prove the exact installed package safely on their own Mac. Another person or machine is not required. File changes alone do not prove the workflow. |
| How close are we? | The roster, skills, hook adapters and CLI foundations exist. The SDK controller, installer completion and exact-candidate proof remain. No release-readiness claim or percentage is justified yet. |
| What starts next? | TASK-3 produces a runnable SDK invocation with result, failure/abort and hook evidence. Then TASK-4 controls one workflow and TASK-5 proves it; TASK-7 repairs reviewer reporting before that proof. |
| What follows 0.1.0? | Keep the conductor role temporarily. Deliver the weaver persona and stitch/weave, then loom, then pulse through the existing ADR-006 tasks and safety prerequisites, before Pi/Codex. |
| Can a smaller version number avoid this work? | No. A prerelease can identify a candidate and disclose limits; it does not prove missing behavior. This checklist targets 0.1.0. |

The SDK lets TypeScript invoke OpenCode sessions and select agents. The controller
must implement stage order, evidence checks, bounded retries and human gates.
The roster defines agent roles; skills supply task procedures; OpenCode hooks
enforce operations at their interception points. The SDK alone does not make
model reasoning deterministic. The current raw-provider reviewer helper does
not automatically load the OpenCode roster, skills or hooks.

After review and merge of this correction, close TASK-45 and start TASK-3 in a
fresh implementation session. Closing this planning task does not complete the
release requirements: they remain in their existing implementation and proof
tasks. Main shows merged progress; run the dashboard from the active task
worktree for live progress. Merge task records with implementation changes.
No new tracker, broad audit, anti-yak-shaving skill or backlog redesign is a
prerequisite. Choose later refinements from actual use.

| Command | Job |
|---|---|
| `weavelog init` | verify required external-tool prerequisites through pinned instructions, then materialize shared skills and OpenCode-native configuration from declared package inputs; normal conflicts refuse; confirmed `--force` replacement preserves a protected backup; does not install external tools |

| `weavelog check` | deterministic gates: tests, lint, typecheck, semgrep (telemetry off, pinned rulesets), secrets, frontmatter, manifest completeness |

- Manifest: JSON (`weavelog.json`), CLI-managed; per-tool install channel (brew/pipx/npm/uv)
  + version + doctor check id. Completeness rule: every external binary invoked in skills/src/payload
  must appear in manifest (check-enforced).
- Ledger: append-only JSONL at ~/.local/state/weavelog/; every command logs files touched,
  decisions, errors, exit code. Zero silent failure: refusal = log line + non-zero exit.
- Post-flip ~/.agents: shared open-standard skills only. Host behavior rules
  live in each verified host's native configuration root; for OpenCode, that
  is `~/.config/opencode/AGENTS.md`. No git, node_modules, or state under
  `~/.agents`. Sync state → ~/.local/state/weavelog/.
- Host-specific plugin files are CLI-managed artifacts (src/hooks/, emitted per host).
- ~/.agents/docs → weavelog/docs (privacy sweep gates public flip). Personal second-brain
  notes stay local unversioned. Backlog moves to weavelog/backlog now.

quickstart + docs/cli.md.

## 2026-09-12 correction — canonical CLI distribution contract

The approved target contract is recorded in [ADR-0008](../adr/0008-cli-distribution-contract.md)
and specified in [the CLI vision](../trd/cli-vision.md). Weavelog is an
opinionated, greenfield-first harness. The package fans shared skills to
`~/.agents` and OpenCode-native configuration to `~/.config/opencode`.
`payload/config/harnesses/opencode.json` is strict JSON control metadata;
`payload/config/opencode.jsonc` is the full human-maintained OpenCode
configuration template.

Normal target conflicts refuse before writes. An explicit `--force` can
replace only an eligible declared leaf file after confirmation. The CLI first
preserves an opaque `.bak` in protected local state and journals the action.
Scaffold creates the four docs homes and does not manage `.gitignore`,
`.env`, `.env.local`, or `.git`. This section records target behavior; TASK-29,
TASK-30, TASK-66, and TASK-67 own implementation and release proof.
